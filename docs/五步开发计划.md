# StarShop 成品 Demo 五步计划

日期：2026-11-13。基于已完成的首版经营原型，继续交付可直接游玩的竖屏演示。

| 步骤 | 工作内容 | 可检查的交付物与验收 |
|---|---|---|
| 1. 数值对照 | 从原Unity物品工厂代码中核实基础价值、商品层级和差价，选24种适合简化经营的参考物品 | 商品数值对照表；每项有方法与常数依据；区分原作基础价和本Demo简化倍率 |
| 2. 美术制作 | 对照柜台/库存/人物/纸面面板截图，以相近暗紫灰、青灰、米黄的像素语言重新设计素材 | 原创商品图、四种顾客和柜台背景；保留可重建资源源文件，不再使用字母方块占位 |
| 3. 竖屏整合 | 将店面、当前顾客、交易报价和底部库存工具组织成手机触控流程 | 一屏突出当前交易；保留仓库、升级、账本；不复刻横屏拖拽和键盘交互 |
| 4. 可玩性验证 | 跑收购/鉴定/出售/跨日/周租/升级/保存恢复，检查低资金和满仓恢复路径、数值周转及响应式布局 | 自动测试、不同宽度运行截图、长程经营模拟；明确微信真机尚未验证 |
| 5. 成品交付 | 构建H5和微信小程序，提供可直接点击的本地游玩地址及可重复启动的离线演示包 | 成品Demo、启动说明、测试记录、提交并推送仓库 |

## 范围

保留现有五笔成交一天、七日周租、无离线收益或惩罚、操作后本地保存。固定报价不议价。游戏仍以空间站收购转售为主，不加入养殖、战斗和复杂制作。

商品基础价值尽量直接采用原作可核实常数；品质、损坏折价、顾客预算、热销和升级等简化规则如没有原作证据，必须明确标为本Demo设计，不能称作还原原作。

美术对照本地原游戏截图和素材的外观进行原创绘制。原作PNG、纹理、字体、人物和Logo不复制到产品或仓库。视觉上遵循原作的金属边框、纸质账单、正面柜台、下部库存和低饱和像素色阶。

## 操作限制

不自动打开桌面浏览器、编辑器或微信开发者工具；测试仅用真正headless Chromium。此前用户许可后台Unity渲染截图仍只用于参考采集，本轮不需要再次启动Unity。
