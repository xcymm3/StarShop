# StarShop 成品 Demo 五步计划

## v0.5 原作交互修订（2026-11-14）

1. 先修订首版方案：保留既定轻量规则，明确四个物品区域和延期机制。
2. 还原实物搬运：鼠标/触摸拖动、落点预览、旋转、取消、碰撞、收回与保存失败回退。
3. 还原收购：顾客台面来货、柜台待购、撤回、确认扣款、收购后整理，以及独立整批折扣。
4. 还原出售：按柜台实物报价、逐件拒收、重复品特质、共享预算、实际成交子集与未售货保留。
5. 验证交付：28项规则、12项无窗口浏览器测试、三种子正常首周交租、双端构建和离线HTML；更新说明并提交推送。

本轮交互以首版方案v0.5为准。后续工具鉴定、标签、容器、整日来客队列继续延期；不能把本轮结果称作全部原作机制已经还原。

## v0.3 简化移植修订（2026-11-14）

以下五步取代旧版的“固定报价、列表仓库、四入口”范围，实施细则见首版方案v0.3。

1. 修订首版方案，明确八项缺口、原作参考与手机简化边界。
2. 实现真实格子、柜台暂放/归属、多件选择、旋转与旧档迁移。
3. 实现未知品质、买后鉴定、独立顾客偏好预算、一次还价、声望、日结账单与理货恢复。
4. 按原作已有截图重排同一工作台，接入统一单步接口，保留既有原创重绘素材。
5. 从新局验收完整首周交租、边界和竖屏UI，构建双端与离线Demo，提交并推送。

## 范围

保留现有五笔成交一天、七日周租、无离线收益或惩罚、操作后本地保存。固定报价不议价。游戏仍以空间站收购转售为主，不加入养殖、战斗和复杂制作。

商品基础价值尽量直接采用原作可核实常数；品质、损坏折价、顾客预算、热销和升级等简化规则如没有原作证据，必须明确标为本Demo设计，不能称作还原原作。

美术对照本地原游戏截图和素材的外观进行原创绘制。原作PNG、纹理、字体、人物和Logo不复制到产品或仓库。视觉上遵循原作的金属边框、纸质账单、正面柜台、下部库存和低饱和像素色阶。

## 操作限制

不自动打开桌面浏览器、编辑器或微信开发者工具；测试仅用真正headless Chromium。原作资料仅使用既有录像和静态分析，当前禁止启动Unity或任何桌面窗口。
