# StarShop 单步游玩接口 v0.5

接口用于由操作者逐次决策，未内置自动经营策略。React UI、H5接口和命令行都使用同一个 `PlayerController` 与纯规则。正式接口没有资金、日期、商品工厂或品质修改入口。

## H5

`window.starshop.observe()` 返回资金、日期、可见商品、当前来客、报价、暂放、租赁账单、日结、可执行动作及禁用原因。未知品质返回null；不返回随机种子、真实隐藏品质或议价容忍度。返回值是脱离内部状态的快照。

`window.starshop.act({ id, token, reason, action })` 只执行一个动作。id为8～80位字母数字/下划线/连字符，token使用刚才观察所得值，reason写操作理由。过期观察拒绝执行。最近200条请求保留幂等收据，旧token仍会拒绝；不要用新token人为重放旧交易。每步先存档，保存失败不公布成功状态。

动作：接客next、送客dismiss、检视identify、暂放/选货stage、撤下unstage、确认收购buy、整批折扣收购wholesale、收回自有柜台货collectCounter、出售sell、一次还价bargain、格子移动move、自动找位autoPlace、清仓clearance、升级upgrade、付款payRent、延期deferRent、确认日结ackDay、应急理货startJob/completeJob。

`move` 的参数为uid、area（warehouse/counter/showcase/customer）、x/y（从0开始的格子坐标）、rotated（boolean）。自有货可在仓库、展示柜、柜台之间移动，包括已列入报价的货物；移出台面会撤回报价。未购来货仅可在customer与counter之间移动，不能转入自有区域。stage/unstage是自动找位的便捷搬货入口，不是与位置分离的选货开关。observe另返回tradeRows（接受与拒收原因）、wholesalePrice、displayCategory及四区尺寸。

收据记录理由、前后状态token、现金前后值与差额、前后日期、入库/移除/移动/鉴定的商品ID。库存归属与所有格子布局在原生存档中保存。近200条审计保存在存档，单次调用同时返回最新玩家观察。

## 命令行

不需要浏览器，也不会打开任何桌面程序。仅能读写 `artifacts/play/` 内的专用接口存档，不访问浏览器现有存档。

```powershell
npm run play -- --file artifacts/play/shop.json init
npm run play -- --file artifacts/play/shop.json observe
```

观察后选择一个动作，把实际token、请求ID、理由和action作为JSON传给act：

```powershell
npm run play -- --file artifacts/play/shop.json act '{"id":"decision-0001","token":"观察得到的token","reason":"核对来货后暂放","action":{"type":"stage","uid":"观察得到的物品ID"}}'
```

init拒绝覆盖已有档。没有从头到尾自动经营的CLI命令。

## 完整周验收

规则测试用三个新局种子42、77、20261114。浏览器用新局77。验收策略只读取上述公开观察，逐次提交正常操作，35笔交易、7张日结、第7日账单真实扣款120、正常进入第8天。没有给验证局注入金钱、改日或创建测试顾客。

证据为 `artifacts/full-week-proof.json` 与 `artifacts/screenshots-v05/`。边界规则测试中另有局部状态夹具，用于满仓、坏档、部分交租等异常；这类夹具不算完整周证明。微信真机和长期经济平衡尚未验证。
